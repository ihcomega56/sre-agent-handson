# 追加シナリオのアイデア

このハンズオンの構成のまま、または少しだけ手を加えて試せるシナリオの候補です。

- **ファイアウォール ルールの削除**: PostgreSQL の `AllowAllAzureServicesAndResourcesWithinAzureIps` ルールを削除して接続不可にし、Activity Log から変更を特定させる。
- **接続文字列の誤設定**: App Settings の `SPRING_DATASOURCE_PASSWORD` を誤った値に変更し、認証エラーと構成変更の関係を特定させる。
- **CPU 高負荷とスケールアウト提案**: CPU を消費するエンドポイントに負荷をかけ、App Service プランのスケールアップ／アウトを提案させる。
- **スロー クエリの傾向分析**: インデックスのない検索 API を追加してデータを増やし、依存関係の応答時間の悪化を Scheduled Task で検知させる。
- **DB 接続数・ストレージの予兆**: PostgreSQL の `active_connections` や `storage_percent` の増加傾向を Scheduled Task で監視させる。
- **デプロイ スロットのスワップバック**: ステージング スロットを追加し、不具合版をスワップ → Agent に承認付きでスワップバックさせる。
- **App Service の再起動ループ**: 起動時に失敗する設定（不正な `JAVA_OPTS` など）を入れ、Platform ログから原因を特定させる。
- **証明書・シークレットの期限切れ予兆**: Key Vault を追加し、期限が近いシークレットを Scheduled Task で棚卸しさせる。
- **定例レポート**: 毎朝、前日のエラー率・応答時間・コストの要約を作らせて Teams やメールに送る。
- **Autonomous モードとの比較**: 応答プランを Autonomous に変えてシナリオ 1 を再実行し、承認なしの自動復旧を体験する。
- **カスタム サブエージェント**: DB 調査専用のサブエージェントを作って応答プランに割り当て、調査の質を比較する。
- **ナレッジの追加**: Runbook を Agent のナレッジとしてアップロードし、リポジトリ経由の参照と比べる。
